# 功能核对表 v0（落地方案 v2 第 6 节）

- 维护：Hark。版本：v0（2026-11-05，spike/native-chat）。负责人 11-06 回意见。
- 规则：每个 PR 描述写上改动的 F 编号；标「新界面已有」必须有证据；改成「以后」要负责人同意并在送审包单列；**删掉一个功能必须所有者确认**；「LobeHub 现有」的每件事单独一行，是关 LobeHub 的依据。
- 状态只有四种：**新界面已有**（之前就有）／**前端本轮补**（本轮 spike 补上，证据见列）／**需 Core**（前端等接口，接口好之前不放入口）／**以后**（待负责人同意）。
- 指南章节按《界面功能 UI 设计指南》v1.1 的编号（1 设计变量 · 2 窄栏 · 3 会话栏 · 4 顶栏 · 5 对话区 · 6 输入卡 · 7 对话功能 · 8 设置 · 9 成员 · 10 资源库 · 11 工具 · 12 API · 13 收件箱 · 14 登录与引导 · 15 手机 · 16 建议）；指南全文未到，章节号以 v1.1 为准再校一次。
- 来源缩写：D213-n = 商用就绪清单第 n 项；v6 = 负责人交接包 v6；M5–M8 = 商用收费版计划；D157–D172 / D173–D180 / D205–D216 / D217–D222 / D235–D243 = 对应裁决；记忆 = 项目记忆；LH = LobeHub 现有；所有者 = 所有者原话（日期）；自审 = ui-self-audit-2026-11-05。
- 证据：`test/<文件> › <用例>` 为 vitest 用例；`unify3-*.png` 为本轮截图（review/ui-shots/<提交号>/）。
- 验收人：负 = 负责人；所 = 所有者；H = Hark 自验。
